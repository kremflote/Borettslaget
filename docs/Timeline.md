# Timeline

Job: what each **phase** of the course project is meant to achieve, its concrete steps, and its status. Phases are this repo's "waves". Dates from L1 p. 6 (may change; check Canvas/TimeEdit).

Status values: PLANNED | IN PROGRESS | DONE | DROPPED

## Rules

- Only the current phase and the next 2–3 carry full detail. A DONE phase collapses to a short outcome.
- Steps reference course docs and Scrumwise; they don't copy them. The backlog itself lives in Scrumwise.
- Steps marked **[req]** come from the course or case; the rest are **[suggestion]** and can be dropped.
- Updated by the Maintainer role (see `docs/roles/Maintainer.md`).

9. Decide where product code lives (separate repo?) and the prototype stack (Figma and/or frontend).
10. Start an evidence log for reflection notes: decisions, obstacles, feedback, changes (L1 p. 10).
11. Watch for course material on the Design Sprint method and exam requirements; add it to `sources/` when it arrives.

Done when: group registered and confirmed, PO contact established, DoD draft and team agreement exist, Scrumwise backlog started, risk register started, Design Sprint plan known.
