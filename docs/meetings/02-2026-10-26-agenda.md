## Scrum basics: what we need before Sprint 1 (30 Nov)

Course-required or assessed items vs. suggestions:

| Item | What it is | Status in course | When needed |
| --- | --- | --- | --- |
| Product backlog in Scrumwise | Prioritised list of user stories ("As a… I want… so that…") with acceptance criteria | Scrumwise use is assessed (L1 p. 10); backlog and stories taught (L1 pp. 26–29) | Start after the Design Sprint direction; ready for Sprint 1 planning |
| Story points 0–5 | Relative size of each story | Decided. Bigger than 5 = split (L2 p. 34) | During backlog refinement |
| Definition of Done (DoD) | One shared checklist for when the team's work counts as finished. Applies to the whole increment, not one story; acceptance criteria are per story | Taught (L2 pp. 10–13). Sprint output is work done per the DoD (L4 slide 6); review demos only DoD-done work (L4 slide 23). **Not listed as a separate deliverable** | Before Sprint 1 planning |
| Risk assessment | List of what could go wrong, how likely, impact, response | Assessed (L1 p. 10); no method given | Start early, update each sprint |
| Retrospective minutes | Notes from each retro: what went well, what didn't, actions | **Required for every retro** (L4 slide 45) | End of each sprint |
| Reflection material | Shared and individual reflection notes | Assessed (L1 p. 10). A running log is our suggestion | Throughout |
| Version control | Git repo for prototype code/design | Assessed (L1 p. 10) | Before Sprint 1 |

Assigning a named owner to each item is a practical suggestion, not something the course asks for. The course says the whole team shares responsibility (L1 p. 23) and organises its own work (L3 slide 24).

Example DoD (a draft to discuss, not from the course): story meets its acceptance criteria; code reviewed by one other member; tested in the browser; merged to main; PO or our stand-in PO has seen it; docs updated if needed.
